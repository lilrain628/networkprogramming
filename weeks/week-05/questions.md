# Вопросы для самопроверки

1. В чем главное концептуальное отличие GraphQL от REST?
2. Что такое Schema Definition Language (SDL)?
3. Чем Query отличается от Mutation? Могут ли они выполняться параллельно?
4. Что такое "резолвер" (resolver) и кто его вызывает?
5. Как решается проблема N+1 запросов в GraphQL (dataloader)?
6. Почему в GraphQL сложно реализовать кэширование на уровне HTTP (как в REST)?


1.  **В чем главное концептуальное отличие GraphQL от REST?**
    В REST под каждый ресурс обычно создается отдельный эндпоинт, который возвращает фиксированную структуру данных. GraphQL использует один эндпоинт, и клиент сам описывает в запросе, какие именно поля ему нужны, получая ровно то, что запросил.

2.  **Что такое Schema Definition Language (SDL)?**
    Это язык синтаксиса, на котором описывается структура GraphQL API. С помощью SDL определяются типы данных, их поля и связи, создавая таким образом контракт между клиентом и сервером.

3.  **Чем Query отличается от Mutation? Могут ли они выполняться параллельно?**
    Query используются для чтения данных и не вызывают побочных эффектов, а Mutation — для изменения данных (добавления, обновления, удаления). Так как Query безопасны, сервер может выполнять их параллельно, тогда как Mutation выполняются строго последовательно, чтобы избежать конфликтов данных.

4.  **Что такое "резолвер" (resolver) и кто его вызывает?**
    Резолвер — это функция, которая отвечает за возврат данных для конкретного поля в схеме GraphQL. Когда приходит запрос, GraphQL-движок (сервер) вызывает соответствующие резолверы, чтобы собрать все запрошенные данные.

5.  **Как решается проблема N+1 запросов в GraphQL (dataloader)?**
    Проблема N+1 решается с помощью паттерна DataLoader. DataLoader группирует все запросы за определенный промежуток времени в один пакет (батчинг) и кэширует результаты, чтобы для похожих данных не приходилось несколько раз ходить в базу.

6.  **Почему в GraphQL сложно реализовать кэширование на уровне HTTP (как в REST)?**
    В REST каждый эндпоинт — это конкретный URL, который легко закэшировать по его адресу. В GraphQL все запросы идут на один URL, но тело запроса (query) каждый раз разное, поэтому HTTP-кэширование не понимает, какие данные нужно сохранить. Кэширование здесь обычно реализуют на уровне клиента (например, Apollo Client) или с помощью специальных персистентных запросов.
