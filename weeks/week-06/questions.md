# Вопросы для самопроверки

1. Зачем нужны `variables` в GraphQL запросе? Почему нельзя просто склеивать строки?
2. Из каких полей состоит стандартный JSON-запрос к GraphQL серверу?
3. Почему у GraphQL обычно только один URL endpoint?
4. Что означает наличие поля `errors` в ответе сервера? Может ли оно прийти вместе с `data`?
5. Как клиент должен обрабатывать ошибки, если HTTP статус ответа 200?
6. В чем плюсы использования типизированных клиентов (например, Apollo Client или Relay) перед простыми HTTP-запросами?

1. Переменные нужны, чтобы безопасно подставлять данные в запрос, а склейка строк опасна легко ошибиться с кавычками или сломать запрос.

2. Стандартный JSON-запрос к GraphQL содержит поля query (текст запроса) и variables (переменные), иногда operationName.

3. У GraphQL один URL, потому что клиент сам описывает, какие данные ему нужны в запросе, а не в адресе.

4. Поле errors означает, что что-то пошло не так, оно может прийти вместе с data, если часть данных всё же удалось получить.

5. Если HTTP статус 200, но есть errors — клиент должен обработать ошибки из этого поля, игнорируя успешный статус.

6. Типизированные клиенты дают автоподстановку, проверку типов и готовый кэш, а простые HTTP-запросы — только отправку строки.
